Research Tool, under the hood

What runs, who calls whom, and what each piece of data turns into, from the moment you open the app to the finished report. It was traced from the code, and every step names the file and function that does the work.

Every block has an ID. The modules are B browser, H Rust host, M middleware and P peripherals (the mock backend today), and the flow steps are S0–S14. To ask about one, quote its ID, for example "explain H7" or "what happens in S11 if two lenses disagree".

The map

Four processes, three wires

The browser never talks to the middleware or to Claude. Everything goes through the Rust host, which owns the document. The middleware owns the thinking. The peripherals (the mock backend) stand in for the model, web research and the shared knowledge store.

Rust host

The OS layer. It owns the document file: every write goes through it and every write is recorded as a decision. It knows nothing about research.

H1

napkin-web router + tenant

crates/napkin-web/src/{main,lib,api,tenant,state}.rs

An axum server. The cookie napkin_tenant (a UUID) is your workspace. /api/* needs the cookie. /s/* is for app frames and uses a token instead. On first use of a workspace it installs every .clan from NAPKIN_WEB_SEED.

Actor
human:<tenant uuid> on every write
H2

Sandbox gate, tokens, quota

crates/napkin-web/src/{sandbox,tokens,meter}.rs

/s/{token}/{route}. The token maps to (tenant, doc) with a 12-hour lifetime, and an unknown token gets 403. Every api-proxy call costs one unit of quota, except job_status. The route is passed to napkin-host's dispatcher.

Quota
NAPKIN_AGENT_CAP, default 40 per tenant per process; we run 400
H3

Session

crates/napkin-host/src/session.rs

One open document (LRU of 32). perform() locks, runs an operation on the snapshot, writes the resulting change, and moves the snapshot to the new version. The version is the sha256 of the archive.

H4

Read ops

crates/napkin-host/src/ops/read.rs · view.rs · html.rs

human_html injects window.__CLAN__ = {data, manifest, assets}. clan_context_for_agent builds the document block sent to the middleware. attach_extracted_text adds file text or images to the payload. view::resolve serves the installed app's newest HTML.

H5

Edit ops

crates/napkin-host/src/ops/edit.rs

patch_data: merge-patch (RFC 7396), check against the schema, record a decision, and create a new revision. upload_asset: store the file and extract its text into human/assets/.extracted/ in the same write. set_title.

H6

api-proxy + settle

crates/napkin-host/src/proxy.rs · session.rs:499-557

It wraps the app's payload as {request_kind, payload, clan} and posts it to workspace.yaml → proxies.middleware.endpoint. If the reply carries a change, it hands it to H7 and returns the new data to the app.

Never sends
scope, tenant or idempotency key
H7

Apply a middleware change

crates/napkin-host/src/ops/middleware.rs:137-377

It checks the doc id and the structured reasoning (R1). It detects a stale base and turns conflicting fields into contests. It appends facts and findings, rebuilds the projection, and prepends the decisions with actor process:middleware, all in one archive write.

H8

Decisions view

crates/napkin-host/src/ops/decisions.rs

Read-only. It turns the chain into blocks for the Decisions panel: who decided, what it touched, what needs attention, and the lock list (open contests, unverified findings, bad verdicts, unmerged branches).

H9

clan-sdk

crates/clan-sdk/src/{pack,instantiate,container,decision,manifest}.rs

The format library. instantiate makes a document from an app. pack validates, prepends a decision, compresses the chain, and makes a new revision. The container is a ZIP with the manifest first.

H10

Store on disk

crates/napkin-web/src/store.rs

<data>/<tenant>/documents/doc-…clan and <data>/<tenant>/apps/<app_id>/app.clan. Every write rewrites the whole file. There is no base-version check yet (W2-A4).

Now at
~/Documents/Code/napkin-os-wt/stack/data

Middleware

Python and FastAPI in server/napkin. This is where research happens: stages, model prompts, rules, merging and reasoning. It never writes the document; it proposes changes, and the host applies them.

M1

Task endpoint

server/napkin/app.py:108-257

POST /v1/tasks. It checks request_kind == middleware, rejects scope keys in the body (rule M3), then branches on the task: job_status, answer_question, start_campaign, short tasks and long tasks.

Scope
from config (org/dev-agency, brand/dev-brand), never the request
M2

Registry

server/napkin/registry.py

An explicit map from task to handler (start_campaign@1, answer_question@1, …). It resolves against the document's own app/pipeline.yaml. Unknown tasks or handlers fail loudly, and every pipeline is checked at startup.

M3

Capabilities

server/napkin/capabilities.py

Each job gets a caps object: model.structured(), research.search(), retrieval and layers, each behind a process-wide semaphore and tagged with the job id. Handlers can only reach the outside through this.

M4

Campaign job

server/napkin/pipeline/campaign.py:120-305

A daemon thread running six stages in order. Each stage emits a chunk (patch, facts, findings, decisions, message), computed once so that repeats are identical. It keeps a working copy W of the document. It pauses on a question and resumes on an answer.

Lives
in memory only (JobStore, max 500)
M5

Stage code

pipeline/extract.py · campaign.py (identify, select) · research.py · synthesise.py · report.py

Extract, identify, select, research, synthesise and report. Each stage makes one or more structured model calls, then code checks everything the model said: quotes must be verbatim, numbers must match, and cites must resolve. See S8–S13.

M6

Researcher fan-out

server/napkin/pipeline/research.py:98-484

One unit per lens × market, run on a thread pool. Each unit tries to reuse recent layer facts, otherwise it does web research → registers sources → extracts facts → checks quotes. Then everything is merged into pins or contests.

M7

Rules

server/napkin/rules/*.py

Deterministic code the model can't override: quote finding, market codes, budget bands, source tiering by domain, confidence from tiers, merge, cite checks, identify rules.

M8

Reasoning (R1)

server/napkin/reasoning.py

Builds each decision's reasoning: decided, because (with cites), rejected, certainty, and would_change_if. The model supplies "grounds". Code drops any point whose cites don't resolve, and certainty is always set by code, never by the model.

M9

Port clients

model.py · research.py · retrieval.py · layers/http.py

Model: an Anthropic or OpenAI-compatible wire with structured output, validated locally and retried once. Research: POST /v1/research. Layers: scope in headers, a deterministic Idempotency-Key on writes, and any failure raises LayersError.

Peripherals (the mock backend)

One standard-library Python process on :8797 in mock-backend/. It fakes the four services the real deployment will have. It holds no middleware logic; it stores, searches and generates. Model answers come from a fresh claude -p run each time.

P1

Router

mock-backend/server.py

It routes by path prefix to the four families, logs one line per request (never the body), and answers /healthz. MOCK_FAKES switches families on or off.

P2

claude -p runner

mock-backend/common.py:224-417

A fresh process in an empty temp dir, with no session, no settings and no MCP. The system prompt goes through a pipe and the schema through --json-schema. There are 4 slots shared by all families, with a disk cache for research and retrieval.

P3

Model port

mock-backend/model_port.py

/v1/messages (Anthropic) and /v1/chat/completions (OpenAI/NIM) translate to claude -p with the schema and hand back structured_output. Never cached.

P4

Research port

mock-backend/research_port.py

POST /v1/research runs claude -p with WebSearch and WebFetch tools, returning sources with verbatim excerpts. Results are cached by query. It does not check that quotes are really on the page; the middleware's own quote check is the guard.

P5

Retrieval port

mock-backend/retrieval_port.py

/v1/packs and /v1/retrieve search the award-corpus digests in engine/packs_dist, and each quote is checked verbatim against the file. The Research Tool never calls it; only Brief Maker does.

P6

Layers port (SQLite)

mock-backend/layers_port.py

The shared knowledge store: categories, brands, rosters, sources and versioned facts, with each fact written together with its decision in one transaction. Scope comes in headers. Writes need an Idempotency-Key; the same key with a different body is a 409 (the bug we fixed in 82bcf22).

Worth knowing

What the trace turned up

These came out of reading the code for this page. None is fixed here; each is a candidate for a decision or a task.

risk

App frames have no CSP on the web

The sandbox blocks the shell and cookies, but the Research Tool frame can fetch any URL, so a hostile app could send document data out. The strict CSP (connect-src 'none') is applied only to offline files. AppRuntime.tsx · wasmFrame.ts:25-45

risk

No lease and no version check on writes

Two tabs, or a person and the middleware, can write the same document. The host catches stale middleware changes (they become contests), but the store itself overwrites the whole file without checking the base (W2-A4). napkin-web/src/store.rs:103-112

risk

Any layers error stops research

A single failed layers write inside one lens unit fails the whole research stage, as with the 409 we just fixed. Research and model errors are contained as gaps; layers errors are not. research.py:325

gap

Lock can never succeed today

Every finding starts unverified and blocks lock, and Verify/Reject is a preview-only dialog. So any campaign with findings can't be locked yet. Building W2-O2 (the verify, resolve, verdict and lock routes) is what unblocks it.

gap

Jobs live only in middleware memory

A middleware restart, or a machine reboot like tonight's, drops every running campaign. The report stage also waits for the host to poll back, so closing the tab pauses the job at report until you reopen it.

gap

Your confirmations carry no structured reasoning

The Research Tool's Confirm and Resolve send a one-line rationale. R1 structured reasoning is enforced only on middleware changes. Whether people must give reasons on these edits is your call.

info

One middleware identity for all web tenants

napkin-web sends no scope, and the middleware takes scope from its own config (org/dev-agency). In this setup every workspace writes into the same layers scope. That's fine for dev, but it needs the credential-to-tenant mapping before real agencies.

info

The view guesses who you are

The host knows your tenant but does not tell the app. The view uses a saved reviewer id, the newest human: actor in the chain, or asks you to type one ("Your user id").

info

Research doesn't use the award corpora

Retrieval (P5) is wired and healthy, but only Brief Maker calls it. The Research Tool gets everything from web research and the layers.

info

Small leftovers

The mock's default data dir is hard-coded to an old session scratchpad path (common.py:42). pipeline.yaml's header still says "No handler code exists". The research port sends no scope headers (open item O8).
